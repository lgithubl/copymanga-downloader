# RJ01234887：EV010 · 页7 渲染修复

目标：`www/data/Map098.json::event-10-7`（豪宅2F）。

## 已复现的问题与原因

原始页有 158 条事件指令，包含角色状态条件、公共事件对话包及循环跳出。旧版编译结果虽然包含70个步骤、图片和63个候选对白语音，但默认可达路径没有台词，只保留初始 `CG-Sisroom-EX`。

原生条件 `[4,2,6,15]` 是角色2是否具有状态15。已对照本游戏 `js/rpg_objects.js` 的 `command111`，子类型6明确调用 `actor.isStateAffected(n)`；并非装备。States.json 的状态15是影响该场景差分的隐藏状态。

旧逻辑将其记为 condition-unhandled，没有产生条件结果变量。前端对缺失变量的正向和反向条件都不成立，因此 if 与 else 两边都消失。只在本地探针中补入该条件结果0即可恢复台词，确认因果关系；正式修复前的回归测试复现失败。

第二个问题：原页在调用对话包后用113跳出112/413循环；旧版未处理跳出，某些阶段会继续展开不应播放的后续对话。对应的独立回归测试同样先失败再修复。

## 修复

- 通用 RPG Maker 支持角色状态条件（111 / Actor / State）。
- 支持原生313状态增加/移除，涵盖指定角色、全队和变量指定角色，条件与公共事件作用域沿用现有运行时变量。
- 新参数 `actors.states` 可以指定初始角色状态，例如 `{"2":[15]}`。未配置时按新游戏没有状态处理，并明确提示未读取原存档；不推测隐藏状态。
- 循环内使用独立执行标记；113只退出当前事件内部最近的循环，保留循环后的正常指令。没有执行退出条件的循环只走一次并保留 loop-repeat-not-simulated 诊断，不模拟无限玩法循环。
- 参数表同步，gal-layout 2.71.1。

没有改通用条件比较器，也没有把所有未支持条件强制判成false。
