# Gal 浏览缓存调度与持久化首页

问题：首次/签名变化时请求等待上下文构建；目录/摘要过期时同步计算；刷新先删缓存再等新首页；多游戏只有按key单飞、没有全局重建上限。服务重启丢失全部内存上下文。

实现：增加数据快照层，命中兼容旧页先返回，检查/刷新进入单进程共享并发1队列；后台构建通过AsyncLocalStorage识别嵌套上下文任务，避免排在自己后面死锁。页面与配置分键、同游戏任务合并；手动刷新不会先清掉可用页面。上下文任务共用队列，请求内共用prepare Promise。保留旧上下文以便失败回退；LRU取代超过200条清空全部。

首页快照原子写data/cache/gal-browse，其他页内存64MiB/256页。代码与配置指纹不兼容不复用；恢复快照后后台预热。每10秒最多一次进入检查、5分钟到期、自动错误退避30秒。首次无可用结果仍需建立。场景解析/分类/配音规则和进度ID不变；原游戏图音资源不复制。容器预展开和资源解码继续沿用原路径，不冒充已被整个迁到后台工作线程。

UI：底部缓存按钮、原生dialog显示状态/文件/场景数量/阶段/原因/耗时/排队/持久化时间/错误；刷新后不导航，手动应用更新才重取当前完整node ID并恢复滚动位置。状态轮询关闭页面后停止，不触发重建。
