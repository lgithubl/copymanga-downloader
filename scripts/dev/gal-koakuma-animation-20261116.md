# RJ01319586 动态CG接入（2026-11-16）

## 原来的缺口

原游戏的主动态CG不是直接播放APNG文件，而是由 `fm001_Koakuma_Touch.js` 选择 `img/pictures/HCG_anime/` 内的PNG序列，按30fps同步绘制人物和背景。`APNG/`目录主要是其它效果帧，不能把它的存在当成主CG已经播放的证据。

此前只支持通用图片、PictureAnimation静态单元切换和声音指令，没有支持这层原生动画调度。素材与控制源码已齐全，不需要Windows，也不需要安装或下载解码器。

另外确认了两个实际阻挡：

- 原事件的109/409注释块里有测试调用及115退出。旧适配器把注释内指令也执行了，导致例如common-468在动画前就退出；现已跳过原生注释块。
- 原静态CG通常在picture51，动画人物/背景在8/7。原插件首次绘制会隐藏旧CG并淡入，结束时恢复。仅加动画而不处理这一步，会被高层静态CG或黑场遮住；现已对应处理。

## 数据读取与隔离

原生 `fm001_Koakuma_Data.js` 只当数据读取：严格识别ListTouchMission/ListMemory的构造器字面量参数，支持引号转义，拒绝表达式；不eval、不执行游戏JS。数据读取限8MiB。

EXE封装资源视图额外将这份已索引的原生表复制到应用cache；原始EXE与素材只读。没有任何运行时网络下载、Python/Unity依赖或新增软件包。缺少帧、未知资源组/动作及缺少任务映射会产生诊断，不静默冒充完整支持。
