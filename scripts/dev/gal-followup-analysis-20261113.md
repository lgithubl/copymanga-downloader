# 2026-11-13 跟进：旧 KiriKiri 布局回归与缺图问题

## 旧 KiriKiri：已确认 tag 脚本回归

ツヴァイトリガー布局用 `data.xp3 + fgimage.xp3 + evimage.xp3` 自动探测，排序还在通用 KiriKiri 前。旧游戏可以同时满足这些条件，导致原有 `scn.xp3 → script` 被换为 `data.xp3 → script`。2.59.0 的同家族结构变体优先探测又扩大了这个影响范围。

2.60.0 取消该布局自动认领，并移除同家族专用布局优先搜索。只有明确的 `krkr::twiv` / `krkr::zweitrigger` 使用ツヴァイトリガー布局；Remastered 同样添加明确的 `edo::Remastered` 别名。通用家族恢复原路径规则。对已误认成ツヴァイトリガー、实际存在有效 scn.xp3 的目录，重跑 gal-layout 会修复布局及错误 ID。

**旧 krkr 适配器代码未修改。** 新回归测试使用有效 Hxv4 加密档案，故意同时放入两种布局所需文件，分别验证自动识别、旧自定义 ID、错误 twiv ID 的配置，并真正解出 scn.xp3 的剧情文字，避免只检查“配置对象没报错”。原生ツヴァイトリガー显式 ID 导入和 PBD 测试仍通过。

## シロクロ：白4第85句台词框

已用原始 `12_エンディング白4■` 复现 ui=false。原生 system.text 明确在消息窗关闭时调用 winopen(0)，而适配器只在 textl/textr 恢复显示。现所有原生 text 调用都恢复消息窗；文字本身、说话人、语音和图层状态仍按原脚本。Node 指定句测试及浏览器窗口透明度测试覆盖这个问题。

## Remastered：sc6000 的后续场景

两个实际原因：原生 global_config 的 `IS_USE_HSCENE=1` 未载入；此外 AdvG[4001] 等已发生剧情标记没有存档，之前全按0处理。原文816组消息，关闭原生 H 场景配置时约137个有效步骤，打开配置后约304个；AdvG[4001]=1 时又能进入原本跳过的 EV156 场景。

现从原生 global_config/global2 读取严格的常量赋值，不执行 Lua，明确的用户初始变量仍优先。Remastered 配置为未确定的 AdvG 布尔剧情标记提供分支选择；同一标记选择后保持一致，已明确配置的标记不重复询问。不会把所有剧情标记强制设为完成。

测试从实际布局参数编译 sc6000，通过生成的选择历史进入 EV156，并核对真实画面命令可以到达。三张指定原图另列在1.59补采中，**没有把未拿到的 EV156 图片宣称为已完成浏览器像素验证**。

## 中途开始：全部适配器共用

以前脚本卡片依赖 config.sceneMarkers，规则空或匹配错就没有按钮。现公共浏览层统一补足：优先明确规则，其次实际 CG/Live2D/视频命令，再回退到可达正文的25%/50%/75%位置。保留进入分支所需的选择历史。没有可用中间位置的极短场景不会生成无意义按钮。

原有“更多→中途开始标签”继续默认开启、按每个 G 单独保存；关闭只影响卡片展示。原生ツヴァイトリガー导入测试检查实际卡片收到跳转点。

## RJ328940：文本接续不等于画面接续

Map336/EV004 进入 Map081 后，CG 使用原生事件284（更换远景图），例如 `img/parallaxes/_Lize_SceneA_00.png`。上一轮只跟进了正文，未实现284，所以没有画面。现将284转换为背景，并在目录证据中纳入图像；42条原生场景图切换均生成画面命令。图中人物属于整张CG，不需要另造一个立绘图层。

原始 Map081 是170个消息窗口，每窗最多4条401、最多55字；保持101/401的原生窗口分组，不把所有正文串成一个步骤，也不将每条排版行伪造成一次消息。真实加密CG原图的两张连续变体已加入1.59补采，以补足显示端验证。

## RJ01271506：立绘包装已修，模板CG仍待证据（2.61.0）

原生Map062/event1/page2在首句前调用common12。该公共事件通过CommonEventExtend复制变量1..5作为参数，再用this._name、switch(this._arguments[n])和$gameSkit.processCommand选择身体、服装、位置和出场方式。之前这些都被记为script-unhandled，随后表情指令也无法显示默认隐藏的身体。

新增有限语句翻译：完整匹配常量局部赋值、参数移位、有限switch及TRP显示调用，生成带条件的播放器状态指令。每个调用独立保存参数/局部变量；按原插件配置读参数，不执行游戏JS。仅RJ01271506 profile启用wrapperScripts，其他RPG默认关闭。未知的地图/存档服装查询保留raw并沿用源脚本已给定的服装，不能声称恢复了未知存档状态；非法/混合任意JS整个语句拒绝。

已用实际Map062而非合成show指令验证首句的Bisty身体+表情、参数5对应right站位，以及原生common10退出。实际加密normal.png_与texture.png_通过导入/资源端点解密，浏览器6763个身体和表情像素采样与独立合成结果一致。

CG仍未全部修好：Common1501是只有正文和局部图片单元变化的片段，不能替代完整调用入口。启用的TemplateEvent明确引用Map093/094/095/096/097/098/251/252，这8个文件在此前采集中没有。采集器1.60默认只取这8张地图，清单合计约5MiB，不重收四作素材、不收运行时/存档；源码只读、长度/SHA和16MiB总量守卫。已同步默认启动分支，等待原生模板后继续核对CG初始化与目录入口。
