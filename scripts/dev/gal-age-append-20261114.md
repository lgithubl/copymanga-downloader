# AGE 追加包与特殊场景入口

原始索引确认 append01 有 14 个剧情脚本及 20 个 CG 文件，append02 有 11 个剧情脚本及 36 个 CG 文件（图片计数包含差分，不等于剧情数量）。旧目录表达式漏掉 `$1$SG0807A–E`、`$2$SP0222A/B`。追加脚本里的普通 ID 54 指向主包 REPLAYVOICE，带高字节的 ID 才指向追加索引；旧实现将普通 ID 当作当前包本地编号，并拒绝高字节脚本/图片编号。

修复将资源 ID 保留为 `group * 0x1000000 + localOrdinal`，低编号始终指向主包。图片、语音和脚本分别建立全局 ID 映射，资源路径仍保留原包命名空间。追加包共用主包 BGM 表和原字体；尚无可靠映射的高字节 BGM 控制仍不猜测。初始化读取追加包的完整纯字面量表，按主包已验证的 32 槽调用数组登记追加 EVINIT/CSINIT 等原脚本。不执行 EXE、DLL 或原生游戏运行时。

AGE 的 catalog 之前绕过 config.views，即使配置了「特殊场景」也没有目录。本次新增适配器声明 catalogViews 的通用接入点，只有主动声明的适配器启用，现阶段仅 AGE。首页展示虚拟视图；名称/路径/跳转标记匹配、更多里的规则编辑/本地覆盖/恢复默认均接通。原脚本 ID、进度、原包目录和用户显式 config.nodes 保持原有归属。默认规则按原生 SP 脚本筛选，包含字母后缀，当前索引共47项：主包42、追加一1、追加二4。CG 跳转点表达式同时识别 `$1$`/`$2$` 前缀。

采集1.72取得两个追加包的原始 BIN。执行追踪确认实际样例使用 EV402/EV503/EV504，而非单纯取档案中的第一张图片；采集1.73只补这三段执行路径引用的23张 CG/差分，约16.7MiB，三份索引 SHA 守卫，原目录只读。按用户的自动采集机制主动检查并下载上报。

验证范围：

- 原始 `$1$SP0203`、`$2$SP0222A`、`$2$SP0222B` 分别执行出65/80/82段正文，包含正确原包 CG 和差分、主包私用字体；7个字母后缀入口不再漏掉。
- 正式导入、layout、普通追加列表及特殊场景列表通过；默认47项，路径规则可只选追加二A/B，CG标记匹配包含三个样例，规则覆盖后的数量和本地状态正确。
- 浏览器从特殊场景进入三个真实样例，实际操作更多里的应用/恢复；每段验证首帧、连续推进8句后的差分、进度续播中段，9处画面与原图合成像素一致。原字体、上一句和续播通过，JS错误为0。证据在 `.cache/age-append-reader/browser/verification.json`。
- 原 AGE adapter、SP0023、开场/G0001、原生导入、布局守卫、导入下拉、旧 KiriKiri 布局及 BGI 回归。
