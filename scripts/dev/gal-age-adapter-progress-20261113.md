# AGE adapter：第一阶段实现与实际显示验证

日期：2026-11-13。最新状态：**已接通导入方案、layout、ALF 剧本/资源及原生语音解码；天結い整段剧情仍未完整可播放。** 导入下拉已加入 AGE SYS4 通用选项，标注开发中；gal-layout 为 2.64.0。当前不把“能导入目录”作为“已支持完整游戏”的结论。

上一阶段不存在必须等待用户处理的阻塞，不应在只完成基础适配器后停止。下面是继续实现和实测后的状态。

## 已实现

- 独立 `age::sys4` 适配器及 `age-sys4` 脚本解码入口；输入是 `age-sys4/1` 包，携带完整 BIN 的 base64。执行时再校验字节码，不信任调用方提供的指令列表。只匹配自己的格式，旧 krkr/kk/BGI 的识别条件未改。
- 补齐 0x64 数组读取和整数数组复制。数组参数、长度、目标地址、总解析量和 VM 内存受限；146 处、697 个元素与上游逐项一致。30 个 BIN 的 185,890 条指令重新对比，参数/文本/数组均无差异。
- 使用已有的分支、函数调用、跨 BIN 调用、局部变量恢复和全局状态追踪；不将整个文件按物理顺序拼成台词。
- 主文本窗口的文本片段、注音、换行和等待输入；按等待点形成播放器步。尚不猜测说话人或其他文本窗口的用途。
- 已确认绘图原语转成现有 `overlay`：保持来源裁剪矩形、原始尺寸和舞台坐标。新增只保留纹理元数据的路径，场景转换无需复制 RGBA 像素；原像素模式保持。
- voice/BGM 指令接口分别绑定。原生语音按 INI/AAI 命名空间中的 ordinal 映射，并通过原始 FIA0026.XWM 的 ALF 读取、FFmpeg PCM 转换及 Chrome 非循环播放实测。BGM 主索引的逻辑编号表已接通：逻辑号减 2 查 SYS4INI 的资源 ordinal 表；不使用档案内重复的 id。BGM 0 停止，1 保持未映射，追加组高字节编号仍未支持。
- 未实现操作码静态清单记录数量及来源偏移（包含不可达代码）；执行遇到未知指令、缺映射/脚本、越界或超预算立即终止正常解析。诊断 API 可保留部分结果，正常 `parse()` 会抛错，不能将残缺场景交给播放器当作成功。

## ALF 与缓存行为

- 单个 AGE 根读取 SYS4INI.BIN 和同目录 AAI，命名空间分别维护；不能用重复的 entry.id 代替资源 ordinal，也不能把追加包的 ordinal 0 当成主包的 ordinal 0。
- 同名外置资源优先于 ALF 内条目。采集中 `$1$SC6870.BIN`、`$1$SCINIT.BIN`、`$1$SCJUMP.BIN`、`VIINIT.BIN` 的外置文件大小与索引不同；测试按原始外置字节保留，报告 archivedSize 和实际 size，没有强行截断或塞回旧长度的档案范围。
- 只有剧本包展开到 `age/script`；图片尺寸查询只读取有上限的 AGF 头部，不预解码整张图。AGF 转 PNG、XWM 转 PCM WAV 在请求时执行。语音使用已有 FFmpeg，限制为本地 RIFF 输入和 file/pipe 协议，不下载编解码器。
- 输入/中间音频保留在 `age/cache/audio`。重建成功才更换脚本树；旧 script/res 移动到 `age/archive`。索引、ALF 或外置文件的签名变化会使缓存失效，防止继续使用旧图片/语音。重建失败时保留上一版，错误进入标准容器报告。

## 输入启用、静态绘图完整返回与音频淡出（f28511e 阶段记录）

本次确认并实现以下有限路径，未增加依赖、未运行 EXE/DLL，也未增加运行时下载：

- `0x94`：旧处理函数 `418c10 → 403fb0(10000)` 设置输入启用状态和导航列跨度；它不等待输入、不立即跳转。外层 `411be1/411fd5` 才检查事件并派发目标。上一阶段称其为等待点过于保守，现已更正。
- `0x1ad`：`4190d0` 记录执行槽位；诊断保存本地调用身份，不将其宣称为完整线程实现。
- `0xae`：`418cd0` 先检查 `+5d798`，新建 VM 为 0 时直接继续。所有置 1 的位置位于原生恢复路径，分支还明确读取 `set:SaveVersion1`、`set:SaveVersion2`。适配器没有加载原生存档，因此只实现新运行分支，并在统计中报告 `nativeSaveLoaded:false`。没有实现原生存档恢复。
- `0x242`：`4247c0 → 49cf70` 写入绘图记录 `+2d0`；消费者 `48b94f/48c854` 在定时属性更新中读取 bit 0，不能解释为隐藏图像。当前支持的静态绘图只保存策略 0/1，不改变可见性或坐标；未支持的定时更新操作仍会终止解析。原生摆放函数现在能正常返回。
- `0xc2`：`420500 → 47aa70/47abb0` 插值音频增益。已确认首参数 0 为淡出，第二参数表示毫秒；SN0000 的 `(0,5000)` 转为通用 `bgmStop {fade:5}`，不插入脚本等待。非零目标增益仍未支持，不猜作播放编号。

- 实现 `0x220` 的平面线性平移子集：旧版处理器 `423460 → 49c990` 写入延迟、时长和目标矩阵，`4ac3b0` 确认平移矩阵布局，`48c2bf..48c641` 对矩阵元素作线性插值。原生 SN0000 把 EV901A（1600×1844）在 1600×900 舞台上于 80 秒内纵向移动 944 像素。
- 播放器新增通用 `overlayMove`。同一次移动有独立 key，普通翻句继续播放；后退/直接跳入按状态重建显示终点。延迟及动画速度沿用已有播放器配置。活动中的再次平移、位置查询、重画以及非平面移动尚未确认时仍明确拒绝，不能随意取终点继续算。
- 图形策略 `0x242` 为 1 的移动不阻塞更新屏障，其余移动在 `0x21c` 屏障中按剩余时长等待；和显式计时器取最大值。解析器只产生 wait，不真正 sleep。
- `0x21b` 保存原生输入保护状态。`0x1c7/0x1cc` 仅实现新运行普通速度的查询结果（0），依据 `42bdc0/42be40` 及初始化 `40cacd/40cb03`。没有模拟原生鼠标事件或原生存档；浏览器快进处理已生成的场景，不改变离线脚本分支。查询不会取消已登记回调。

实际验证：

- Chrome 用原生脚本产生的移动命令和 EV901A 解码图验证 0/40000/80000ms：每帧 66,891 个采样像素均无差异；40 秒翻句后继续移动；后退的实际画布与终点参考一致。诊断结果保存在 `.cache/age-adapter-display/native-pan-verification.json`。浏览器测试使用可控 RAF 时钟，不实际等待 80 秒。
- 像素测试两侧统一使用 CPU 2D 画布，避免 Chrome 多次 getImageData 后只把一侧从 GPU 切至 CPU 引起不同插值。这是测试设置，未修改生产图像插值行为。

最新默认变量诊断链停于 `SN0000 @20984 / 0x224`。旧处理器 `419c60 → 499a80 → 4994e0` 清空图形管理器的 `+418` 树，而已支持的绘图对象在 `+408`；尚未把这个清空错误映射为清空所有叠加层，也没有将其当作无操作跳过。下一段仍涉及图形辅助对象及资源切换。完整 SYSTEM4 初始化和原生事件调度未完成，当前默认变量诊断链不能视为真实初始化后的完整开场。

## 辅助表、整数清零、对象清理与停止淡出（最新）

- 已实现 `0x224`：只清理图形辅助表 `+418`，不清理 `+408` 持久绘图对象或纹理。当前已接受的指令不会创建辅助表项；`0x223` 等尚未确认的创建指令仍明确失败，因此没有跳过已创建但无法渲染的内容。
- 已实现 `0x6c`：从整数地址/指针起清零连续 count 个单元；count <= 0 不写。旧处理器 `42b8a0` 填充 `+5eb98`，而 `405450` 表明该字段是 rol(key,21) 的加密零；不能把它解释成非零脚本常量。全局、本地、指针和范围上限有测试；数组复制/清零合计最多写入四百万个单元，避免单条批量指令绕过执行预算。
- 已实现 `0x1f7`：原生 `422270 → 49b060/49b230` 对单个 ID 或半开 ID 区间删除绘图记录，count <= 1 时仍删除一个对象；纹理保留。转换为对应 slot 的 overlayOff，可取消对象尚在进行的移动；不删除任何磁盘文件。
- 已实现 `0xb8`：`419100 → 47a8b0` 立即停止当前 BGM。实际播放器原先把淡出的 Audio 与当前 BGM 分离，随后立即停止可能漏掉这份旧 Audio；现已跟踪淡出项并在立即停止、跳转到无 BGM 状态、销毁时停止它们。新曲仍恢复正常配置音量。
- Chrome 以真实 XWM 转换得到的 WAV 验证播放→80 秒淡出→立即停止→新曲→后退→销毁，无残留播放；结果在 `.cache/age-adapter-display/bgm-stop-verification.json`。该 WAV 在此测试中仅用作可解码音频夹具，不宣称对应原生 BGM 绑定。

验证：20 项 adapter、12 项核心 VM、实际 ALF 导入链、原生 CG 三帧像素/翻句/跳转、上述音频生命周期、旧 Edo 浏览器回归、8 项布局守卫及导入下拉验证通过。没有增加镜像依赖或运行时下载，没有运行 Windows 游戏。

新的确切边界：`SN0000.BIN @2833 / 0x35c`，271 条原始执行指令。它出现在从 SNINIT 的四列参数表读取数据、随后设置 BGM 13 的执行链中，和 `0x35d/0x35f` 相邻；据此推测涉及播放范围/循环控制，但未把推测写成执行语义。已将返回正常的 SNINIT、61 行原始表值及调用位置保存到 `.cache/age-adapter-display/new-audio-controls-evidence.json`。曲目 13 的四个参数都是零，也不能仅凭零值就跳过未确认的操作。

当前主 EXE 和 AGE.EXE.org 的原始解释器代码仍受保护。已静态恢复出的嵌套 PE 是保护器加载器，不是解释器；进一步反汇编加载器并发现 AES 表，不等于已取得密钥或解开原程序。公开 Kelebek1 工具的 `age-shared.cpp` 对 `0x35b/35c/35d/35f` 和 `0x304/305` 仍只有操作码/参数数量，未提供执行实现。源码已移至 `/tmp/Eushully-Decompiler` 复用，编译产物及以往分析仍保留。

因此整段游戏仍未验收，也没有发布完整支持版。目前已向用户询问是否已有同版本解密后的 EXE 或解释器代码导出文件；这是继续准确确认新版行为的额外依据请求，不是再次索要剧情 BIN。没有执行或擅自切换到此前用户暂不使用的 Windows 方案。


## Mac 可独立完成部分的收尾（2026-11-14）

本轮继续只做数据解析、静态核对及本机 Chrome 验证；没有执行 AGE.EXE/DLL，没有增加镜像依赖或运行时下载。完整原生游戏仍未验收。

- 初始化执行框架：支持显式 `initialization` 顺序，数据全局整数/字符串/浮点共享，各根和被调用 BIN 的局部状态隔离。初始化未知指令、预算耗尽、需要原生输入或未提交绘图批次/计时器时禁止进入正文。没有把数据辅助函数冒充完整启动，也没有自动选择原生菜单。
- `0x2d5`：依据 `42f690 → 41bae0/42a430` 实现单精度浮点赋值。INIT2 的前 12 个真实浮点写入通过；未提供依赖时仍准确停止于 SCINIT ordinal 22929（@340），不将整段 INIT2 记为完成。整数操作不隐式接受浮点存储。
- 回调：`0x7b` 注册目标自身不表示普通推进时应执行。旧原生消费者分别受事件位保护，因此更正此前“任何回调注册都会阻止正文结束”的过度限制。实现显式分析事件重放与 `0x7c` 返回，保存被打断 PC、局部状态和函数栈；跨 BIN 调用后恢复正文，不允许嵌套回调或用普通 return/exit 代替回调返回。BIN 结束释放自己的注册，函数返回不释放。连续 300 个调用不泄漏槽位。
- 原生 GUI/输入区域派发仍未实现。带有效目标的输入区域在输入等待/脚本结束处继续明确阻断，不能静默绕过剧情选择。显式回调重放只用于有依据的分析输入，不映射浏览器任意点击。
- `0x2f6`：`425d60 → 4a9d00 → dsStop(12+slot)` 重置三个语音辅助通道。已接受的 c4 播放使用 slot 0，转换为通用 `voiceStop`；另外两个通道尚无已支持的播放生产者。停止语音不停止 BGM、不释放资源。
- `0x2f8`：`425e00 → 4a4e60 → 4a5630` 最终调用 `IDirectSoundBuffer::SetPan`（vtable +0x40），错误字符串也明确是 dsbSetPan。零是声像居中，绝非静音。当前只实现居中，非零仍拒绝，避免用音量近似声像。
- 播放器停止语音时清除活动引用、结束自动推进所跟踪的记录；隐藏后重新显示不恢复已停止语音。后退/直接跳转也停止上一句语音。

完整 SYSTEM4 默认入口先重置三个通道，再调用 **2023**（其中将三个通道声像居中），随后仍停止于 **@16 / 0x35b**。此前组件测试显式执行的 **2040** 只是另一个数据辅助函数；不能据其正常返回声称完整初始化已通过。SNINIT + CVINIT 的真实数据初始化可顺序完成并供受控正文读取，但也不能替代完整 SYSTEM4。

本轮验收区分三层：43 项核心/adapter/真实 ALF 导入测试；真实素材的 Chrome 图像/语音/移动组件显示；受控字节码经过正式 parse 后的标记跳入、后退和离屏缩略图。受控测试使用真实 CVINIT/SNINIT、AGF/WAV，但不声称它是原始剧情执行顺序。浏览器证据保存在 `.cache/age-adapter-display/`。旧 Edo 浏览器、BGI 58 项、krkr 布局、8 项布局漂移守卫及导入下拉通过。

剩余确切边界仍是当前版未知指令（完整初始化 `0x35b`、独立开场 `0x35c`、文本尾部 `0x305` 等）以及完整原生 GUI/剧情输入派发。Kelebek1 仅给这些新版指令参数数量，没有执行实现；当前 EXE 解释器代码仍加密。没有把它们跳过，也不发布“整段支持完成”的 release。现有开发中 `age::sys4` 导入下拉保留，旧家族匹配范围不变。
